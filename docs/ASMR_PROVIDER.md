# 6단계 ASMR 공급자 연동 결정 사항

현재 `AsmrProvider`는 교체 가능한 서버 경계다. 운영 기본값은 `DisabledAsmrProvider`이며 생성 요청은 503 `GENERATION_UNAVAILABLE`로 거절한다. 테스트 프로필 `asmr-test`와 `EMORI_ASMR_TEST_GENERATOR=true`를 함께 설정하면 `TestAsmrProvider`가 30초 무음 PCM WAV를 만든다. `postgres` 프로필에서는 이 구현을 활성화할 수 없다. 테스트 음원 제목에는 `Test fixture`가 들어가며 실제 AI 생성 품질을 검증하지 않는다.

## 공급자 선정에 필요한 답

- 한국어 감정 단어와 선택적 설명을 입력으로 받을 수 있는지, **무보컬·무가사**와 트랙당 **30초 이하**를 계약과 결과에서 강제할 수 있는지.
- 안정된 요청 키를 통한 중복 방지, 비동기 작업 ID 저장 및 상태 재조회, 타임아웃과 취소, 결과 파일의 재다운로드 기간을 지원하는지.
- 출력 포맷, 실제 길이 측정, 라이선스와 이용자 재생·보존 권리, 데이터 보관 및 제3자 전송 정책, 사용량 제한·대기 시간·트랙당 비용.
- 실패·재시도·동일 요청 재전송 시 과금 기준과 장애 시 복구 절차.

## 연동 시 남은 작업

1. 선정 공급자용 `AsmrProvider` 구현, 서버 자격 증명과 운영 프로필 등록, 생성 프롬프트에 최대 30초·무보컬·무가사 정책 고정.
2. 공급자 응답을 PCM WAV로 변환하거나 검증 가능한 다른 포맷으로 계약 변경. 현재 워커는 PCM WAV 헤더·데이터 길이와 신고 duration의 일치를 검사한다. 음성·가사 부재와 청감 품질은 별도 자동/사람 검증이 필요하다.
3. 로컬 파일 저장소 대신 서버 간 공유되는 영구 객체 저장소 채택, 백업·접근 정책·보존기간·고아 파일 정리 기준 결정. 파일 저장 성공 후 DB 커밋 실패 또는 늦은 lease 결과는 참조되지 않는 파일을 남길 수 있다. 현재 자동 삭제는 하지 않는다.
4. 실제 공급자·네트워크 장애·서버 재시작·모바일 기기에서 생성 시간, 중복 과금, 재생·재열람을 통합 검증.

공급자가 요청 키 또는 작업 조회를 제공하지 않으면 요청 직후 연결 장애가 났을 때 **중복 외부 생성과 중복 비용을 완전히 방지할 수 없다**. DB는 늦은 결과가 확정된 트랙을 덮어쓰지 못하게 막지만, 공급자 측 생성 횟수까지 보장하지 않는다.
